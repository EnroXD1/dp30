# ДП-30: подключение по Wi-Fi без USB и ADB

Для подготовленного Windows-стенда (папки `dp30` и `work/dp30-tools` рядом). Существующие файлы запуска не заменяются. Используется тот же PostgreSQL и те же два процесса FastAPI. Обычный HTTPS остаётся на 127.0.0.1:8443; отдельный Caddy принимает Wi-Fi-подключения на TCP 8444 только на выбранном локальном IP.

## Запуск

1. Распакуйте четыре файла архива в корень репозитория, сохранив папку `ops`.
2. Включите мобильный хот-спот Windows или подключите компьютер и телефоны к одному доверенному роутеру. Убедитесь, что устройства могут обмениваться данными (на некоторых гостевых сетях включена изоляция клиентов). Хот-спот Windows зависит от наличия поддерживаемого адаптера и его настроек; при необходимости используйте роутер без WAN.
3. Запустите `Start-DP30-WiFi.cmd`. Выберите интерфейс точки доступа (часто 192.168.137.1). Можно указать адрес явно: `Start-DP30-WiFi.cmd -LanIP 192.168.137.1`.
4. Скрипт создаёт локальный CA и сертификат с IP в SAN, собирает APK (нужен JDK 17 и подготовленный SDK; при первом запуске Gradle могут потребоваться загруженные зависимости), запускает обычный сервер и запрашивает разрешение UAC для ограниченного правила брандмауэра. Используйте только доверенную сеть. На компьютере с уже работающим сервером повторно поднимать базу не нужно.
5. После сообщения `DP-30 Wi-Fi is ready` скопируйте указанный APK (`work/dp30-tools/wifi/<IP>/DP30-WiFi.apk`) на телефоны любым способом и установите. USB-отладка не требуется. Для установки может потребоваться разрешение на установку приложений из выбранного источника. Если Android не принимает обновление из-за другого ключа подписи, потребуется установить приложение заново (это удалит его локальные данные; сначала синхронизируйте черновики).
6. В приложении откройте «Адрес сервера» и укажите показанный адрес, например `https://192.168.137.1:8444`. Войдите под учебными аккаунтами. На двух телефонах проверьте создание и назначение заявки, её принятие и передачу результата.
7. Чтобы остановить Wi-Fi-прокси, нажмите Enter в окне запуска; обычный сервер остаётся работать. Правило брандмауэра сохраняется для повторного запуска. Если оно больше не нужно, в PowerShell от администратора выполните `Remove-NetFirewallRule -Name 'DP30-WiFi-192.168.137.1'`, подставив свой IP.

## TLS и ограничения

- APK доверяет публичному CA прежнего стенда и CA выбранного Wi-Fi-адреса. Проверка HTTPS и имени узла не отключена. Ключи находятся только в `work/dp30-tools/wifi/`, не добавляйте их в GitHub. Сертификаты действуют год. При истечении срока остановите прокси, переместите каталог `tls` выбранного адреса в безопасное место и запустите скрипт повторно; установите новый APK на телефоны.
- При смене IP повторите запуск и установите соответствующий APK; старый сертификат не подходит новому IP. Фиксированный адрес хот-спота или DHCP-резервация упрощает использование.
- Порт 8444 не надо пробрасывать в интернет. База и внутренние API остаются привязанными к loopback. Не используйте демонстрационные аккаунты для реальных данных.
- Поддерживается именно подготовленный Windows-стенд, не Docker Compose и не отдельный переносимый комплект. Скрипт не включает хот-спот автоматически.
- Проверка /health выполняется с компьютера с проверкой CA и IP. Она не доказывает доступность с телефона; обязательна проверка на реальном устройстве.
