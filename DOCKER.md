# Запуск ДП-30 на Windows через Docker

## Первый запуск

1. Установите Docker Desktop для Windows (Linux containers, WSL 2): https://docs.docker.com/desktop/setup/install/windows-install/. Требуется Docker Compose 2.24.4 или новее (`docker compose version`). Откройте Docker Desktop и дождитесь запуска движка.
2. Скачайте проект или клонируйте его. Поместите файлы этого комплекта в корень проекта рядом с `compose.yaml`. Не заменяйте существующий `compose.yaml`.
3. Для телефона включите мобильный хот-спот Windows либо подключите компьютер и телефон к одному доверенному Wi-Fi. При наличии старого сервера на 8443 остановите его.
4. Запустите `Start-DP30-Docker.cmd`. Выберите IPv4-адрес Wi-Fi или хот-спота (например, 192.168.137.1); вариант 0 — только локальный доступ. Первый запуск требует интернет для образов и pip-зависимостей; последующие не пересобирают образ без необходимости.
5. После сообщения `DP30 Docker server ready` скопируйте показанный адрес и пароль. Окно можно закрыть.
6. Скачайте APK из https://github.com/EnroXD1/dp30/releases (нужна debug-сборка GitHub Actions с поддержкой пользовательских CA). На телефон перенесите **только** `.local/docker-tls/DP30-CA.crt`, установите как сертификат ЦС (CA) в настройках безопасности Android. Не переносите `ca.key` или `server.key`. Проверьте происхождение сертификата и удалите его с телефона после окончания работы со стендом.
7. В приложении на экране входа откройте «Адрес сервера» и введите показанный HTTPS-адрес. Войдите как `dispatcher`, `worker`, `manager` или `admin` с паролем, напечатанным при запуске. Для остальных учебных аккаунтов (`dispatcher2`, `worker2`) тот же первоначальный пароль.

## Сеть и сертификаты

- Выбирайте реальный Wi-Fi/хот-спот, а не VPN, WSL или виртуальный адаптер. Порт 8443 публикуется только на выбранном IP; PostgreSQL и внутренние API наружу не публикуются. В режиме 0 телефон не сможет подключиться напрямую.
- Если требуется разрешить входящие подключения Windows, запустите лаунчер от администратора и подтвердите создание ограниченного правила или выполните предложенную команду в административном PowerShell. Правило разрешает TCP 8443 на выбранном локальном IP из LocalSubnet и сохраняется после остановки. Удалите правило после демонстрации: `Remove-NetFirewallRule -DisplayName 'DP30 Docker HTTPS 192.168.137.1'` (подставьте фактический IP).
- Не пробрасывайте 8443 в интернет; используйте только доверенный Wi-Fi. У некоторых точек доступа изоляция клиентов не позволяет устройствам общаться.
- Постоянный CA сохраняется в `.local/docker-tls/`. При смене IP перезапустите лаунчер и выберите новый адрес; серверный сертификат при необходимости обновится, CA останется тем же. При истечении или утрате CA потребуется отдельная замена и установка нового публичного сертификата на телефоне.
- Сертификаты этого Docker-стенда независимы от прежнего USB/эмуляторного стенда. APK пересобирать не нужно: подпись приложения и HTTPS CA — разные ключи.

## Ежедневный запуск / остановка / обновление

- `Start-DP30-Docker.cmd` — обычный старт. С существующими образами и зависимостями интернет не нужен.
- `Stop-DP30-Docker.cmd` — остановка всех сервисов Docker-стенда без удаления базы.
- `Update-DP30-Docker.cmd` — пересборка серверного образа после обновления исходников (например, после `git pull`), запуск, миграции и проверка HTTPS. При обновлении образа может потребоваться интернет. Перед обновлением сделайте резервную копию.
- С PowerShell можно указать интерфейс явно: `./start-docker.ps1 -BindAddress 192.168.137.1`.

## Данные и диагностика

Лаунчер использует отдельный Compose-проект `dp30-docker`, независимый от обычного запуска и прежнего `docker compose up`. Это новая учебная БД, существующие записи из других стендов не переносятся автоматически. Том PostgreSQL сохраняется между остановками; не выполняйте `down -v` без намерения удалить данные. Сценарий запускает `dp30.demo` для демонстрационной базы; существующие пароли не сбрасываются. Если все заявки удалены, повторный запуск может восстановить демонстрационные заявки.

`.local/docker.env` хранит сгенерированные пароли; не меняйте пароль существующей PostgreSQL без соответствующей смены пароля в БД. `.local/docker-tls` содержит приватные ключи; храните этот каталог и файл окружения только локально, с ограниченным доступом, делайте защищённые резервные копии. `.local/docker-backup` содержит резервные копии базы. Они не должны попадать в Git (исходный `.gitignore` уже исключает `.local/`).

Проверить контейнеры и журналы из корня проекта:

```powershell
docker compose -p dp30-docker --env-file .local/docker.env -f compose.yaml -f compose.launcher.yaml ps -a
docker compose -p dp30-docker --env-file .local/docker.env -f compose.yaml -f compose.launcher.yaml logs --tail 100 https api1 api2 migrate db backup
```

Контейнер `migrate` в состоянии Exited (0) — нормальное завершение миграций. Если HTTPS-проверка не прошла, проверьте журналы, выбранный IP и занятость 8443. При ошибке запуска контейнеры могут остаться работающими; используйте Stop-скрипт перед повторной попыткой. Для резервного копирования используется уже существующий `ops/daily-backup.sh` (каждые 12 часов).

В комплекте не меняются Android, текущий GitHub Actions, `compose.yaml` или старые сценарии USB/эмулятора. Проверено программное создание и обновление TLS-сертификатов; полный запуск Docker Desktop/Windows и подключение телефона требуют проверки на реальном ноутбуке.
